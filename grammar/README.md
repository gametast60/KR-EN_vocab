# คลังไวยากรณ์และ SRS

โมดูลนี้ใช้หน้าหลักและการสำรองข้อมูลร่วมกับแอปคำศัพท์ ปัจจุบันมีบทนำร่อง TOPIK I 12 เป้าหมายการเรียนและโจทย์ 456 ข้อ ส่วน TOPIK II เก็บดัชนีต้นฉบับไว้สำหรับจัดทำบทถัดไป ดัชนี PDF 84 + 148 แถวไม่ใช่จำนวนบทที่พร้อมเรียน และไม่ใช่การรับรองความครอบคลุมระดับสอบทั้งหมด

## แก้เนื้อหาที่ไหน

```text
grammar/
  manifest.json          รายชื่อไฟล์และเวอร์ชันเนื้อหา
  lessons/*.json         หนึ่งไฟล์ต่อการใช้งาน: คำอธิบาย ตัวอย่าง บทพื้นฐาน
  questions/*.json       หนึ่งไฟล์ต่อการใช้งาน: ชุดฝึก จบบท และทวน
  sources/topik-i.json   ดัชนีต้นฉบับ เลขหน้า ข้อความรายหน้า และ SHA-256
  sources/topik-ii.json  เช่นเดียวกันสำหรับ TOPIK II
  generated/content.js  ไฟล์ที่สร้างให้อ่านในเบราว์เซอร์และออฟไลน์ ห้ามแก้โดยตรง
  catalog.js            ตรวจโครงสร้าง รหัสซ้ำ การอ้างอิง และบทพื้นฐานวนซ้ำ
  scheduler.js          นโยบาย SRS และการตรวจข้อมูลผู้เรียน
  session.js            การเลือกโจทย์ คำตอบแรก ผลชุด และการยกเลิกผล
  integration.js        จุดรับเหตุการณ์การฝึกจากเกม
  ui.js                 หน้าวันนี้ คลัง บทเรียน ทวน และความก้าวหน้า
```

เนื้อหาอยู่ในไฟล์ JSON ส่วนข้อมูลผู้เรียนอยู่ใน `five_stage_mvp_v1` ใต้ `grammar` โดยมี schema version ของตัวเอง ไม่เก็บความก้าวหน้าไว้ในไฟล์บทเรียน ระบบบันทึกเหตุการณ์ ผลตาราง และรอบที่พักไว้ใน transaction เดียวกับแอปเดิม

## เพิ่มหรือแก้บท

1. คัดลอกไฟล์บทและโจทย์ที่ใกล้เคียง ตั้ง `id` ถาวรเป็นภาษาอังกฤษ เช่น `ko.eseo.action` หนึ่งรหัสหมายถึงหนึ่งการใช้งาน แม้มีหลายรูปแปร
2. แก้ `title`, `form`, `rules`, `examples`, `scope`, `track`, `order`, `prerequisites` และ `sourceRefs` ให้ตรงเป้าหมาย บทเสริมที่ไม่มีใน PDF ใช้ `sourceRefs: []` และ `origin: "supplemental-foundation"`
3. แก้โจทย์ในไฟล์คู่กัน ให้ `lessonId` ตรงกับบท และรหัสโจทย์ทุกข้อขึ้นต้นด้วยรหัสบท อย่าเปลี่ยนรหัสของโจทย์เดิมเพียงเพราะแก้สะกด
4. เพิ่มชื่อไฟล์ทั้งคู่ใน `manifest.json` แล้วเพิ่ม `revision` ของไฟล์ที่แก้ และ `contentVersion` ของคลัง
5. รันคำสั่งด้านล่าง ตรวจความหมาย ความกำกวม และคำตอบทางเลือกก่อนนำขึ้นใช้งาน

```powershell
node tools/build-grammar.cjs
node tools/build-grammar.cjs --check
node --test tests/*.test.cjs
node tools/serve.cjs
```

เปิด `http://127.0.0.1:8787/#grammar-library` เพื่อดูเนื้อหาจริง เบราว์เซอร์ใช้ไฟล์ generated จึงต้อง build หลังแก้ JSON ทุกครั้ง ไม่ต้องเพิ่ม script tag หรือแก้ service worker เมื่อเพิ่มบท: hash ของเนื้อหาทำให้เกิด cache รุ่นใหม่อัตโนมัติ หากแก้โค้ด runtime ให้เพิ่มเวอร์ชัน CACHE ใน `sw.js` ด้วย

หากเปลี่ยนการใช้งานหรือความหมายอย่างมีนัยสำคัญ ให้สร้างรหัสบทใหม่ อย่านำประวัติเดิมไปอ้างว่าเรียนความหมายใหม่แล้ว บทความหมายเดิมที่อยู่ทั้ง TOPIK I และ II ควรอ้างความรู้เดียวกัน ไม่สร้างประวัติซ้ำตามระดับสอบ ห้ามนำรหัสที่เลิกใช้แล้วกลับมาใช้กับความรู้อื่น ระบบเก็บประวัติที่ไม่พบในคลังไว้ใน backup และไม่ลบทิ้งเอง

## โครงสร้างโจทย์

- `pool`: `guided` ฝึกพร้อมเฉลย, `checkpoint` จบบท, `review` ทวนตามกำหนด
- `skill`: `use` สร้างรูป หรือ `understand` เข้าใจและเลือกใช้
- `type`: `type` พิมพ์ หรือ `choice` เลือกคำตอบ โดยด้าน `use` ต้องพิมพ์
- `contextId`: รหัสบริบท ป้องกันสองข้อในชุดเดียวช่วยตอบกันจากบริบทเดียวกัน
- `accepted`: คำตอบที่ยอมรับ ตรวจ Unicode NFC และช่องว่างที่อนุญาตด้วยรายการทางเลือก ห้ามใช้ fuzzy matching กว้างจนรับคำลงท้ายผิด
- `glossary`: คำศัพท์ที่จำเป็นกับคำแปล ห้ามมีเฉลยของไวยากรณ์เป้าหมาย
- `explanation`: เหตุผลที่ใช้รูปนั้น แสดงหลังจบชุดประเมินเท่านั้น

บทหนึ่งมีโจทย์จบบทอย่างน้อยด้านละ 10 ข้อ เพื่อเลือกครั้งละ 5 ข้อและมีอีกชุดสำหรับลองใหม่ ชุดทวนมีอย่างน้อยด้านละ 8 ข้อ เลือกครั้งละ 2 ข้อ โดยใช้ข้อที่ไม่เคยเห็นหรือเห็นนานที่สุดก่อน และไม่ใช้โจทย์ที่เพิ่งเฉลยภายใน 24 ชั่วโมงในรอบทวนตามกำหนด เมื่อใช้คลังจนครบแล้วข้อเดิมจะหมุนกลับมาได้ จึงต้องเพิ่มบริบทใหม่เมื่อขยายบท และไม่ตีความคะแนนว่าเป็นความสามารถในการพูดสด

ตัวสร้าง bundle ตรวจรหัสซ้ำ ความครบของโจทย์ จำนวนขั้นต่ำ บทพื้นฐาน และการอ้างอิงแหล่งข้อมูล แต่ไม่สามารถตรวจความถูกต้องของภาษาแทนผู้ตรวจเนื้อหาได้ เนื้อหานำร่องเป็นแบบฝึกที่เรียบเรียงเพิ่มจากหัวข้อ ไม่ใช่การนำคำแปลจาก PDF มาใช้เป็นเฉลยอัตโนมัติ

## กติกา SRS v1

- ผ่านจบบทเมื่อได้อย่างน้อย 4/5 ทั้งสองด้าน จึงเข้า step 1 นัดหลังอย่างน้อย 24 ชั่วโมง
- ทวนหนึ่งรอบมี 4 ข้อ: สร้างรูป 2 ข้อก่อน แล้วเข้าใจ 2 ข้อ เฉลยหลังจบ นับเป็นเหตุการณ์เดียว
- 4/4 ขึ้นหนึ่งขั้น, 3/4 ลดหนึ่งขั้น, 0–2/4 หรือเปิดเฉลยกลับขั้น 1
- ช่วงทวน 1, 3, 7, 14, 30 วัน คิดด้วยเวลาจริงและแสดงตามเวลาท้องถิ่น กล่องคำศัพท์เดิมยังใช้กติกาเดิม
- ต้องถึงกำหนดและเว้นจากเฉลย/คำอธิบายอย่างน้อย 24 ชั่วโมง ถ้าช่วงจริงสั้นกว่าช่วงที่กำลังวัด ผลถูกจะคงขั้นและนัดช่วงเดิมใหม่
- การฝึกก่อนกำหนดไม่เปลี่ยนขั้น การตอบซ้ำหลังเฉลยไม่ลบผลครั้งแรก การมาช้าไม่ทำให้ตกขั้นโดยอัตโนมัติ
- เปิดชื่อบทอย่างเดียวไม่ใช่ exposure; เปิดบทหรือเฉลยเป็น exposure และทำให้รอบที่พักไว้ของเรื่องเดียวกันไม่อิสระ
- ชุดประเมินเก็บ snapshot + fingerprint หากอัปเดตเนื้อหาระหว่างรอบ ระบบยกเลิกการประเมินชุดเดิมก่อนแสดงโจทย์ต่อ
- แจ้งโจทย์ผิดคืนตารางก่อนรอบปัจจุบัน เก็บรายงานพร้อมรหัสโจทย์ใน backup โดยยังเก็บเวลาที่เห็นเฉลยจริงไว้
- ใช้ได้ต่อเนื่อง: ผ่านสองรอบทวนติดต่อกัน ต่างวัน และรอบล่าสุดเว้นอย่างน้อย 7 วัน ไม่ลบสถานะผ่านบทเมื่อทวนผิด

ตัวเลขทั้งหมดเป็นเกณฑ์ทดลอง MVP ให้ติดตามผลแยกสองด้าน ระยะห่างจริง เวลาเรียน และรายงานโจทย์ผิดก่อนปรับนโยบาย หากปรับกติกาให้เพิ่ม `policy` และเก็บเหตุการณ์รุ่นเก่าไว้ ไม่คำนวณประวัติย้อนหลังด้วยสูตรใหม่โดยเงียบ ๆ

## เชื่อมเกมเพิ่มเติม

เกมที่สอนหรือแสดงเฉลยเรียก `GrammarIntegration.recordExposure(data.grammar, {lessonId, at, source: 'ชื่อเกม'})` ภายใน `store.transact` การเรียกนี้ไม่ให้คะแนนและไม่เลื่อน SRS

เกมที่จะประเมินจริงต้องสร้างรอบด้วย `GrammarSession.create(lesson, item, 'review', now)` ส่งคำตอบแรกผ่าน `GrammarSession.answer` และใช้ชุด 4 ข้อจนจบ อย่าส่งคะแนนเกมหรือ XP เข้า scheduler เป็นความสำเร็จโดยตรง ตัวอย่างการทำ transaction อยู่ใน `ui.js` เกมใหม่ควรใช้ session engine เดียวกันเพื่อได้การเว้นช่วง การพักต่อ และการป้องกันบันทึกซ้ำครบถ้วน

การเห็นไวยากรณ์อื่นประกอบในโจทย์ไม่เลื่อนความก้าวหน้าของไวยากรณ์นั้น การเปิดศัพท์ช่วยจะบันทึก exposure ให้คำศัพท์ที่ตรงรายการในคลัง แต่ไม่เปลี่ยนกล่องหรือให้ผลตอบถูกแก่คำศัพท์

## ตรวจระบบและข้อมูลสำรอง

`tests/grammar.test.cjs` ตรวจนโยบาย การคัดโจทย์ คำตอบแรก การคืนตาราง migration/backup และการแยกจากข้อมูลคำศัพท์ ส่วน `tests/grammar-browser.cjs` ใช้ Playwright กับ Edge ในโปรไฟล์ใหม่เพื่อตรวจมือถือ IME การพัก/โหลดใหม่ จบบท ทวน แจ้งโจทย์ผิด backup/restore และออฟไลน์ ติดตั้งหรือชี้ `NODE_PATH` ไปยัง Playwright ที่มีอยู่ก่อนรัน

ข้อมูลสำรองเดิมที่ไม่มี grammar จะเพิ่มส่วน grammar ว่างเมื่อเปิด โดยรักษารายการคำศัพท์เดิมไว้ การกู้คืนแบบเลื่อนวันนัดเปลี่ยนเฉพาะ due dates และไม่เลื่อนเวลาหลักฐานการจำ หากข้อมูลไวยากรณ์ผิด schema ระบบปฏิเสธไฟล์และให้เก็บข้อมูลดิบแทนการรีเซ็ตเอง

นำเข้าดัชนี PDF ใหม่ด้วย `tools/import-grammar-pdfs.py <ไฟล์ TOPIK I> <ไฟล์ TOPIK II>` โดยใช้ Python ที่มี pypdf เครื่องมือนี้เก็บต้นฉบับและตรวจเลขรายการครบ แต่ไม่แก้บทเรียนหรือประวัติผู้เรียน ไม่จำเป็นต้องติดตั้ง Python เพื่อเปิดแอป
